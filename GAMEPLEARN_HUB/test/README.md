## ชุดทดสอบ SQL (`sql/t_sql.sh`)

ตั้ง Postgres 16 ขึ้นมาแล้ว **จำลองสภาพ Supabase** ก่อนรันไฟล์จริง:
`auth.uid()` · role `anon`/`authenticated` · RLS ชุดเดียวกับของจริง ·
และ **จงใจวาง pgcrypto ไว้ในสคีมา `extensions` ไม่ใช่ `public`**
เพราะนั่นคือต้นเหตุที่ทำให้ `supabase_patch_all_v7993.sql` ล้มทั้งไฟล์บนฐานจริง
ทั้งที่รันผ่านบน PG เปล่า (`function crypt(text, text) does not exist`)

สิ่งที่พิสูจน์: ห้องของครูคนอื่นไม่รั่ว · ห้อง "โค้ดเท่านั้น" ไม่โผล่ · ไม่มีชื่อนักเรียน/โค้ดห้องหลุด ·
คนที่ยังไม่ล็อกอินทำอะไรได้/ไม่ได้บ้าง · กุญแจรับห้องใช้ซ้ำไม่ได้ · ห้องที่มีเด็กแล้วไม่ถูกเก็บกวาด

**ไฟล์ 64 (ใบรายงานผลของนักเรียน) ตรวจหนักเป็นพิเศษ** เพราะเป็นท่อที่คะแนนทั้งระบบวิ่งผ่าน:
ยิงทีละคนจนครบห้องแล้วให้ใบกลางล้ม · รายการเดียวผิดต้องไม่ลากใบที่เหลือตก ·
เหตุผลทุกแบบต้องเป็นภาษาไทยที่ขึ้นจอครูได้ · และ **ต้องไม่มีทางคืน `ok:false`**
(ภาค 2 ดักด้วย `.catch()` อย่างเดียว — ตอบ 200 พร้อม ok:false เมื่อไหร่ ข้อมูลเด็กหายเงียบทันที)

ไม่มี Postgres บนเครื่อง = ชุดนี้ **ข้ามให้เอง** ไม่ทำให้ชุดอื่นตก

## กับดักที่เคยเสียเวลาไปแล้ว

- `document.body.textContent` **ลากเนื้อในแท็ก `<script>` มาด้วย** — จะเจอคำที่อยู่ในโค้ด
  ทั้งที่หน้าจอไม่ได้แสดง · ให้อ่านจาก `#page-main` หรือ `#content` แทน
- ตั้งค่า `localStorage` **หลัง** `goto()` แล้วเปลี่ยนแค่ `#hash` เบราว์เซอร์ไม่โหลดหน้าใหม่
  `boot()` จึงไม่ทำงานอีกรอบ · ใช้ `page.addInitScript()` ฝังเซสชันก่อนหน้าจะเริ่มรัน
- วัดว่า "ปุ่มอยู่แถวเดียวกันไหม" ด้วยค่า `top` **ไม่ได้** — ปุ่ม `btn-sm` เตี้ยกว่าปุ่มปกติ
  อยู่แถวเดียวกันแท้ ๆ แต่ `top` ต่างกัน 5px เพราะจัดกึ่งกลางแนวตั้ง · ให้วัดจุดกึ่งกลางแทน
- `bar.querySelector('.btn-primary')` ลากของที่อยู่**ในเมนู**มาด้วย พอเอาไปเข้า `insertBefore`
  จะโยน `NotFoundError` แล้วบูตหยุดกลางคัน (ปุ่มสลับธีมหาย + หัวเว็บไม่รู้ว่าล็อกอินแล้ว)
  ต้องใช้ `:scope >` เมื่อต้องการลูกตรง — เจอจริงตอนย้ายปุ่มเข้าเมนูใน V.1.4.3
- **หน้า Admin มีประตูตรวจสิทธิ์** (`teachers.role = 'admin'`) — ข้อมูลจำลองที่ไม่มีช่อง `role`
  ทำให้ชุดทดสอบวิ่งอยู่**หน้าประตูที่ยังไม่เปิด** แล้วผ่านเพราะไม่ได้ตรวจอะไรเลย
- **ตัวดักคำขอเก็บเนื้อ body เฉพาะ POST** — คำขอ `PATCH` จึงมองไม่เห็นว่าส่งอะไรไป
  และเก็บแค่ 200 ตัวอักษร ⇒ `JSON.parse` พังกลางสตริง (แก้เป็นทุกเมท็อด · 4000 ตัวอักษร)
- **`$$` ในข้อความ `raise exception` ปิด dollar-quote ของบล็อก `do $$` ที่ครอบมันอยู่**
  ⇒ ไฟล์ SQL ทั้งไฟล์พังด้วย syntax error · ใช้ป้ายเฉพาะ (`do $guard$`) และเลี่ยง `$$` ในข้อความ
- 404 ของภาพหรือของตารางที่ยังไม่ได้สร้าง **ไม่ใช่บั๊ก** — ชุดนี้จงใจให้เกิด
  ใช้ `realErrors()` ที่นับเฉพาะสคริปต์พังจริง ไม่ใช่ `console.error` ทุกบรรทัด
